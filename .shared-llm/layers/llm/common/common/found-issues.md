## Found Issues — Fix Now or Defer?

When you find a problem during work that is not part of the current task, you must surface it explicitly. Never absorb it silently and call it a "follow-up." Silent deferrals never get done and cause downstream bugs.

**Interactive mode (user is present):**

Stop. One bullet. One question:

- Found: [plain description of the problem]. Fix now or add to a follow-up list?

Default is fix now. Only defer when the user explicitly says to.

**AFK / autonomous mode (no user present):**

- If the issue is blocking the current plan: halt immediately, report what was found and why it blocks, and wait for the user.
- If the issue is not blocking: finish the current task, then surface it as a single clear line at the end: "Found during this run: [what]. Not fixed. Needs a decision."

**Never:**
- Declare something a "follow-up item" and move on without telling the user.
- Assume a non-blocking issue can wait — surface it; let the user decide.
- Stack multiple found issues into a block at the end — one at a time so none gets buried.
