The single kickoff workflow the meta-orchestrator brain sends to a freshly spawned Claude Code TUI session over tmux — one command per phase. Invoked `/meta-auto-run --plan <plan.md> --phase <instructions.md> --output <results.md> --hub <loc> [--team true]`, it runs three existing commands IN ORDER as one driven sequence: (1) `/hub-connect <hub>` registers this session on the hub; (2) `/run_phase --plan … --phase … --output … [--team true]` reads the plan + instructions, dispatches a TeamCreate team (or subagents), runs the mandatory adversarial-evaluator gate, and WRITES results.md with a leading `PHASE_RESULT:` line; (3) `/response --hub … --output …` pings the brain with the verdict + the results.md path. The results.md write in step 2 and the step-3 ping are BOTH mandatory final actions — but because results.md is written to disk in step 2, the brain can detect completion by watching that file even if the step-3 ping is skipped or fails: the file is the source of truth, the ping is only the accelerator. This is the design that removes the old hub-only "forgot to report" fragility — a forgotten ping no longer strands the phase because the result is already on disk. A thin conductor that threads its args through the three commands and never re-implements their logic; all four args are required and it fails loud on any missing.
