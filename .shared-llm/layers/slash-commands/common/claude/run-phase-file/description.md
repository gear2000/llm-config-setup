Run ONE phase of a plan FROM FILES — the file-based worker playbook the meta-orchestrator brain launches per phase. Invoked `/run_phase --plan <plan.md> --phase <instructions.md> --output <results.md> [--team true]`: reads the full plan file AND the phase's instructions file (the instructions carry the phase goal + done-check), does the work by dispatching an agent TEAM via TeamCreate when `--team true` (named teammates in their own tmux windows — the interactive-TUI team feature) or subagents via the Task/Agent tool otherwise, then ALWAYS runs the mandatory `adversarial-evaluator` gate (Opus 4.8, max effort) exactly as `/run-phase` does — the phase passes only on CLEARED. It WRITES the result to the `--output` results.md file whose FIRST line is exactly `PHASE_RESULT: passed|partial|blocked|failed` followed by a `----- REPORT -----` section; that file is the source of truth the brain reads to judge the phase, so writing it correctly (passed ONLY if the work is fully done AND the evaluator CLEARED — never fabricated) is the whole job. The data travels as files under `/tmp/meta-orch/<session>/`, NOT over the hub: this command is HUB-AGNOSTIC, it touches no hub, only files. Fails loud and STOPS if `--plan`/`--phase`/`--output` is missing, the plan or instructions file is unreadable, or the output dir is not writable. The file-based sibling of the hub-arg `/run-phase`; chained after `/hub-connect` and before `/response` by `/meta-auto-run`.
