# Controller requirements

Every workflow in this pool points here. These rules bind whoever runs the workflow: the plan-implementer in Pattern 10, the HIL pane itself in Pattern 20.

- Delegate production coding, fixes, tests, checks and independent reviews through UpAgent. The controller owns scope, briefs, evidence inspection and the next action; it does not code.
- One writer in the authorized checkout at a time. Every reviewer, auditor and finalize stage is a fresh independent worker, never the coder.
- Select existing personas and validate exact offerings and efforts against the current UpAgent listings before hiring. Ask on a missing choice or an unavailable model. Never substitute.
- Record every request, receipt, candidate identity, command, exit code, finding and attempt count in the run status. Resume from that record without duplicate hires and without resetting counters. A changed candidate needs fresh relevant checks and reviews.
- Honour `retries` exactly. After the last loop, stop and ask the human. Never add a silent extra hire, review or audit.
- Preserve human gates and the plan's original acceptance criteria. Only the root HIL talks to the human; an intermediate implementer relays questions through it. Ordinary workers do not hire workers.
- A merge required by the approved plan is not final acceptance and grants no push or deploy authority.
