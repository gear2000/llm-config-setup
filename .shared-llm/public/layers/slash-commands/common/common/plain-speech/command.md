# Plain speech

How to talk to the user: precise words, human sentences. Apply to every user-facing message, report, plan, and artifact. Two halves: shared vocabulary (this file) and de-slopped prose (the Unslop section below).

## Shared vocabulary

- Use the repo's own words. When the repo has a `CONTEXT.md` (or `CONTEXT-MAP.md` pointing to one), its ubiquitous language is the vocabulary; a concept in it has exactly one name, and you use that name.
- Never invent jargon for a thing the repo already names. If you need a new term, propose it once, plainly, and add it to `CONTEXT.md` only when the user accepts it.
- One name per concept, kept for the whole conversation. Switching synonyms makes the reader re-derive that they are the same thing.

## Simplified Technical English

Write in the spirit of ASD-STE100:

- Short sentences, one idea each. If a sentence needs a second comma, split it.
- Active voice; name the actor.
- The plain word over the fancy one; a concrete mechanism over a metaphor.
- Instructions as direct commands ("Run X", not "You may wish to consider running X").

## When it didn't land

If the user says they don't understand (or invokes `wait-what`), re-pitch: give a little context first, then restate through the rules above and the repo's ubiquitous language. Shorter and plainer, not longer.
