# Isolated Herdr 0.9.5 lab

Run from this checkout on Linux x86_64. Download the release to scratch space, leaving the
installed Herdr alone:

```bash
mkdir -p /var/tmp/herdr095-release
curl --fail --location https://github.com/herdrdev/herdr/releases/download/v0.9.5/herdr-linux-x86_64 \
  --output /var/tmp/herdr095-release/herdr
python3 .shared-llm/public/extensions/common/herdr/isolated_lab.py init /var/tmp/herdr095-lab \
  --binary /var/tmp/herdr095-release/herdr --session llm-lab-095
```

`init` verifies the release's published SHA-256, refuses an existing lab directory, and
uses `lab_session.py` to record ownership and provision the named server. The server runs
headless at 160 columns by 50 rows. No TUI attachment is needed. Use a short root because
Unix socket paths have a size limit. Initialization errors leave the scratch directory for
inspection; use a new directory after correcting the error.

Every lab command goes through the environment wrapper:

```bash
python3 .shared-llm/public/extensions/common/herdr/isolated_lab.py exec /var/tmp/herdr095-lab -- herdr status --json
python3 .shared-llm/public/extensions/common/herdr/isolated_lab.py exec /var/tmp/herdr095-lab -- just upagent help
```

Before a full request drill, generate the checkout's ignored public offering roster without a home
deployment. Run this through `isolated_lab.py exec` from the checkout:

```bash
python3 -c 'import sys; from pathlib import Path; p=Path(".shared-llm/public/extensions/common/upagent"); sys.path.insert(0,str(p)); import offerings; (p/"offerings.yaml").write_text(offerings.render_roster(["standard"]))'
```

The wrapper clears the caller's pane, socket, session, and hub environment. It sets both
`HERDR_SESSION` and `HERDR_SOCKET_PATH`, prepends only the copied binary's directory to
the child process's `PATH`, and sets `UPAGENT_CANONICAL_REPO` to this checkout. This avoids
the client's normal re-exec into the primary checkout. Python may read the operator's
installed user packages; its bytecode cache goes into the lab.

The lab contains:

- `home/`: isolated `HOME`, with XDG config, Codex home, Pi agent directory, and Cursor
  config beneath it. Claude reads `.claude.json` and `.claude/` here.
- Copied authentication files: `.claude/.credentials.json`, `.codex/auth.json`,
  `.pi/agent/auth.json`, and `.config/cursor/auth.json` when present. Initial copies have
  mode `0400`. OAuth refresh can replace a lab copy; no credential is linked to its source.
- Minimal Claude onboarding/account metadata and folder trust, empty package settings for
  Pi, Codex file-based credentials with update checks disabled, and copied kit Claude
  personas. Production hooks and settings are not copied.
- Official integrations installed by the lab binary for Pi, Claude, Codex, and Cursor.
  Verify them with `herdr integration status` through the wrapper.
- `state/`, `runtime/`, `cache/`, `tmp/`: separate XDG and UpAgent writable state, including
  `state/services.json` and `state/ledger/`.
- `ownership/`: the guarded session helper's before snapshot and ownership record.
- `work/` and `evidence/`: harness probe files and captured command output.

Create topology before starting agents. Use returned IDs, which are opaque:

```bash
# Prefix each command with the wrapper shown above.
herdr workspace create --label probe --cwd /var/tmp/herdr095-lab/work
herdr agent start probe-pi --kind pi --pane RETURNED_PANE --timeout 60000 -- \
  --approve --no-extensions -e /var/tmp/herdr095-lab/home/.pi/agent/extensions/herdr-agent-state.ts \
  --model openai-codex/gpt-5.6-luna --thinking high
herdr agent prompt probe-pi 'Write probe.txt containing authenticated, then remain idle.' --wait --timeout 60000
```

Start Claude and Codex bare in their own panes in the same way. Inspect first-run screens
with `herdr pane read`. The tested Claude CLI asked for acceptance of bypass mode; the
tested Codex CLI asked for review of its installed SessionStart hook. Resolve those lab
setup screens before submitting work. A successful prompt response alone does not prove
the requested work happened: verify the output file and transcript. Herdr can misclassify
an unfamiliar dialog as idle.

Retain receipts, result bundles, and pane reads under `evidence/` before closing a drill's
panes. When finished, explicit teardown still checks ownership and the non-lab fleet:

```bash
python3 .shared-llm/public/extensions/common/herdr/isolated_lab.py teardown /var/tmp/herdr095-lab
```

Teardown stops and deletes only the recorded named session. It keeps lab files for review.
This workflow never installs into the operator's home or runs `just update` / `just global`.

## Rehearsing an existing home upgrade

The fresh-home lab above does not test migration of installed hooks and settings. The
upgrade rehearsal on 2026-10-21 used a second home at `/var/tmp/hu95-fix1b/home`, the same
verified release binary, and the guarded session `llm-lab-upgrade-095`. Its evidence is in
`/var/tmp/herdr095-fix1b-myfpevt1`; worker drill transcripts and ledgers are in
`/var/tmp/hu95-fix1b/drills`.

The rehearsal copied `.pi/agent`, `.claude`, `.codex`, `.cursor`, `.config/herdr`, and
authentication metadata. Writable files and runtime link targets became lab copies.
Skills could retain their read-only source links. Socket files were excluded, authentication
copies started with mode `0400`, and absolute hook paths were rebased to the copied home.
No installer ran with the real home. Copied Codex daemon PID records refer to real processes;
the interactive probe used `--no-daemon` instead of controlling those processes.

The four official integration installs changed Pi v3 to v9, Claude v7 to v11, Codex v6 to
v10, and Cursor v1 to v2. The normalized before/after diffs show:

- Codex `hooks.json` was unchanged. Both `herdr-status-fix.sh` entries survived.
- Claude `settings.json` was rewritten only at the Herdr SessionStart matcher, from `*`
  to `^(startup|resume|clear|compact|fork)$`. The kit's other hook wiring remained intact.
- Cursor hook configuration and Pi settings were unchanged.

The home-side deployment was reproduced by calling `tools.harness.do_home_runtime` with
the copied home and the machine's global/exclusion settings, without destination settings.
It composed and deployed personas, refreshed generated Claude hooks and statusline, refreshed
Pi runtime links and Herdr config, and materialized the offering roster. Existing settings
were preserved. It does not deploy the Codex compatibility hook. Lab terminal isolation
settings were then reapplied to the lab config. Neither `just update` nor `just global` ran.

First-launch captures show Claude folder trust for the new lab directory; the copied bypass
acceptance was retained. Pi and Cursor reached input without an acceptance dialog. Interactive
Codex showed hook review after hook paths changed in the copied home. Existing hook trust may
avoid that screen on a real upgrade that keeps its paths. A Codex exec probe completed its
file-writing task unattended before interactive hook review was accepted.

The upgraded-home Pi and Codex worker drills passed with Sentinel enabled in 159 and
173 seconds. Both ran the foreground 100-second sleep, calculated and checked 5050,
and published their required bundles. Codex's two legacy reports had been removed.
Claude's Bash tool rejected both the compound sleep and standalone `sleep 100`, each
with `timeout=180000` and `run_in_background=false`. Both requests published blocked
bundles. These are workload refusals, not passing foreground-busy Claude drills.

The interactive Pi pane-close drill has no lifetime `agent wait`. Its hub emitted
`sentinel-wake-worker-gone` 10.889 seconds after the close, within the retained 15-second
probe cadence. Sentinel returned STALLED, and the hub published a typed blocked bundle
with verified cleanup. The original exec pane-close drill in the fresh-home lab emitted
worker-gone about one second after close and ended with Sentinel FINALIZATION_FAILED.
Its separately opened `agent wait` returned in 0.102 seconds; that number does not measure
the hub. Neither close drill hired a separate salvage rescuer or completed the worker task.
