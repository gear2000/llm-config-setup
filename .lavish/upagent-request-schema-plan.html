Locked decisions

The boundaries are settled

Architecture

One Hub + adapters

Worker and specialist intake remain typed modules. Both submit ordinary orders to one ledger, lease, cleanup, completion, and receipt authority. Specialist answers retain their citation gate.

Caller surface

One variadic recipe

An imported upagent +args recipe invokes a thin machine-local client. It never imports or executes the nearest worktree’s Recruiter lifecycle code. No LLM-facing upagent-request versus upagent-consult split.

Offering selection

Stable id + effort

Requests use --offering ID --effort LEVEL. YAML derives the harness, exact model, renderer, and allowed effort set before any ledger or Herdr action.

Single-door routing

Any agent or local user
└── just upagent …
    └── thin client (any checkout or worktree)
        └── machine-local Unix socket
            └── ONE canonical UpAgent Hub process
                ├── strict request + offering validation
                │   ├── worker adapter
                │   └── specialist adapter + citation policy
                ├── single ledger / lease writer
                ├── bounded Account Manager
                └── worker or specialist pane
                    └── typed completion reactor
                        └── bundle + answer + receipt + requester event

The caller’s worktree remains the worker cwd; lifecycle execution, lease mutation, reconciliation, and child-runner code always come from the canonical Hub. Future capacity isolation is a queue lane, never another ledger writer.

Mandatory split-brain amendment

One Hub now means one process-level writer

The reproduced failure is positional: a worktree’s imported Just recipe executes that worktree’s recruiter.py; cmd_consult() dispatches in-process; _spawn_job() launches via that copy’s __file__; meanwhile all copies share /tmp/.upagent. A worktree runner and the main supervisor can therefore mutate the same lease with different code versions. The worker pane is created, its token loses ownership before record_worker, and the pane is orphaned before it can write the specialist answer.

Current failure

Nearest code copy + shared ledger

Shared state: /tmp/.upagent
├── main-checkout Recruiter
│   └── reconciles and changes lease ownership
└── worktree Recruiter copy
    └── creates Herdr pane
        └── record_worker(old token)  ✗ rejected
            └── pane becomes orphaned
                └── specialist answer not found

Failure chain: two Recruiter copies share one state directory; ownership changes after pane creation but before worker recording, leaving no accepted answer.

Transport

Stable local socket

Publish one discoverable socket such as /tmp/.upagent/hubs/<repo-id>/hub.sock. UPAGENT_SOCKET may override it. Every Just invocation connects; none directly calls cmd_dispatch, JobLedger, run-job, or reconciliation.

Single writer

Canonical engine identity

The Hub records hub_instance_id, canonical engine path, protocol version, PID, and Herdr session. An exclusive startup lock prevents a second Hub. All child runners use the Hub’s code path/version, never the caller’s __file__.

Launch transaction

No orphan window

Persist fenced launching intent before pane creation; tag the pane with request + generation; compare-and-swap to started. A failed transition closes that exact pane. Reconciliation can recover or close an interrupted launch deterministically.

Usability first

Callable and requestable by every local agent and user

Deliberately included

  • Machine-local socket readable/writable by local callers by default.
  • No caller registration, user allowlist, role enrollment, API key, JWT, TLS, or per-worktree approval.
  • lists, status, request, await, and specialist requests work from any cwd/worktree.
  • The Hub executes under its existing service account; callers supply the target worktree cwd.

Retained only for correctness

  • Closed request schema and offering validation.
  • Lease generation/token compare-and-swap.
  • Timeout-response nonce to prevent stale decisions.
  • Protocol-version handshake that fails clearly instead of corrupting shared state.

These fences prevent duplicate work, stale writes, and version corruption; they are not caller authorization. Any local caller may submit work. A caller holding the current request event may perform its fenced lifecycle response.

Consult-specific terminal contract

  1. Specialist workers write answer.json to a lease-private staging path, never directly to the public caller path.
  2. Python validates consult id, error/success shape, and required citations, then atomically projects the exact public answer_path.
  3. Omission or malformed output receives one bounded repair; failure then produces a schema-valid Python-authored failure answer.
  4. The consult receipt and requester event publish only after the public answer is readable and valid.
  5. A mandated specialist consult without a cited answer blocks stage acceptance. Reading the source directly is useful diagnosis but does not satisfy the consult requirement.
  6. Same consult/request id + same canonical payload attaches to the existing request; changed payload conflicts. Nine retries create one worker, not nine contenders.

Rule Fail-loud behavior
One request source --file is mutually exclusive with request-defining inline flags. Operational --wait/--json remain allowed.
Closed schema Absolute readable JSON file, one object, schema_version: 1, no unknown keys, and the same worker/specialist conditional fields as the CLI.
Optional caller id Accept one canonical UUID or ULID from either --request-id or the file—not both. If absent, Recruiter generates it.
Idempotent retry Existing id + identical canonical request hash returns the existing request/status and launches nothing new.
Collision Existing id + different request hash exits non-zero with request_id_conflict before manager, ledger mutation, or launch.
Identity separation External request_id is only a lookup/idempotency key; Python still mints the internal order_id, lease token, paths, and control token.
Keep transport controls out of the file: --wait, --json, and notification timing affect this invocation, not the immutable identity of the work. That keeps retries hash-stable and lets the same file be submitted synchronously or asynchronously.

  • Harness exists and has a renderer plus health detector.

  • Every specialist and lifecycle role references an existing offering and permitted effort.

Manifest

Typed required artifacts

Every worker requires result.json, compacted.md, and handoff.md at lease-private staging paths. Specialist requests additionally require a staged answer.json that Python validates and projects atomically to the caller’s exact answer_path.

Manager boundary

Advisory only

The cheap per-request manager observes lifecycle evidence and advises one repair. It cannot alter leases, invent passing artifacts, publish results, or declare terminal state.

Python authority

Always terminal

The canonical Hub’s Python process validates, snapshots evidence, writes fallback artifacts and consult answers, publishes atomically, cleans the pane, writes the receipt, and notifies the requester.

Claude/Codex structured output and Pi JSON/RPC events may improve capture, but they are adapters only. The canonical Hub’s cross-harness Python manifest validation remains the acceptance authority. A stage whose brief mandates specialist input cannot pass without a Hub-verified cited consult receipt.
Implementation plan

Six phases, beginning with a hard single-writer boundary

1

Establish the open canonical Hub

Split lifecycle authority from caller code. Start one canonical Hub behind a stable machine-local Unix socket and exclusive startup lock; publish its hub_instance_id, engine path, protocol version, PID, and Herdr session. Make the socket usable by local agents and users without registration, API keys, allowlists, TLS, or per-worktree approval. The thin client has no ledger mutation, reconciliation, dispatch, or runner-spawn path. All child runners use the Hub’s engine path/version. Add the fenced launching → started transaction and exact-pane compensation so a failed record transition cannot orphan a pane.

2

Put the complete public façade on the socket

Add imported upagent +args with up, status, lists, request, await, await-any, verify, respond, and reconcile. Feed named flags and --file through one closed schema; support optional UUID/ULID request_id idempotency. Client and Hub both validate protocol/schema, but only the Hub mutates state. Every main-checkout, worktree, controller, and legacy wrapper must use this transport; none may call cmd_dispatch() locally.

3

Install the nine-offering roster

Add the validated offerings map, grouped/text/JSON listing, stable-id request resolution, and immutable offering snapshot in order.json. Convert kit specialists and lifecycle roles from raw model tuples to offering references. Keep controller and legacy recipes only as deliberate transport shims that call the canonical socket; none retains a local Recruiter or ledger path.

4

Render exact harness argv from canonical code

Claude uses --effort; Codex uses -c model_reasoning_effort=…; Pi uses provider-qualified --model and --thinking. Unit-test exact argv before Herdr invocation, plus process/agent/cwd startup verification after launch.

5

Finish manager + typed completion reactor

Set dedicated per-request supervision, pinning the lightweight Account Manager to claude-sonnet-5/low. Keep Fable credits opt-in and require explicit worker offerings; any legacy-only worker default uses claude-opus-4-8/max. Add the typed artifact manifest, bounded one-repair transition, Python-authored blocked bundle, atomic publication, receipt, cleanup, and durable requester event. Specialist manifests add lease-private answer.json; Python publishes a cited answer or valid failure answer before the consult receipt. Stage finalization blocks when mandated consult evidence is absent.

6

Verify, document, and vet the public diff

Smoke every selected offering and run the worktree split-brain matrix: main checkout plus multiple current/stale worktrees must report one hub_instance_id, canonical engine path, and exactly one worker for an idempotent consult. Kill the Hub between pane create/record and prove recovery leaves no orphan. Test open local caller access, protocol mismatch, omitted artifacts, answer projection, timeout, crash, stale lease, mandatory-consult blocking, manager failure, and process mismatch. Run LSP diagnostics, just test, just update, docs review, and mandatory independent proprietary-content review before any push.
