Bottom line

Yes—Pi can compact automatically at 50% of the actual active context window.

The audit still stands: pi-ultra-compact does not currently initiate that compaction. Instead of installing it, the recommended thin extension is now implemented. It watches Pi’s authoritative getContextUsage().percent, triggers native compaction after a long-lived TUI or RPC run settles, and lets Pi’s built-in summarizer do the lossy part.

Deployed: automatic native compaction at 50%, with Pi’s native near-overflow compaction retained as a second safety net. The source is symlinked into ~/.pi/agent/extensions/auto-compact.ts; restart Pi or run /reload to activate it.

Mechanism

Why the package’s 50% gate does not fire at 50%

The package put its threshold check downstream of Pi’s trigger. At 50%, no event reaches it. Around 95.6%, Pi finally starts compaction, emits the hook, and only then does the package evaluate its 50%/60% gate.

Decision

Four ways forward

1. Install unchanged

No

Useful only for the manual command or replacing Pi’s summary once Pi is already compacting.

  • Does not independently trigger at 50% or 60%.
  • Current test run has 10 failures.
  • Documentation, defaults, types, and behavior disagree.

2. Fork and repair it

Possible

Add the missing lifecycle trigger and repair the engine, tests, public types, and docs.

  • Retains ~1,500 lines of custom heuristic compression.
  • Large maintenance surface for a narrow need.
  • Harder to prove semantic preservation.

3. Small native trigger extension

Recommended

Use the package’s best idea—the model-relative threshold—without taking its summary engine.

  • Authoritative ratio from Pi, automatically follows model switches.
  • Native turn boundaries, previous-summary handling, and file tracking.
  • Small enough to test end-to-end and understand completely.

4. Wait for Pi upstream

Eventually

Upstream issue #4129 proposes a native contextRatio trigger.

  • Best long-term ownership boundary.
  • Not available in the installed Pi 0.80.6 settings surface.
  • Our extension can be deleted when upstream lands.

Proposed design

Keep the trigger custom; keep compaction native

1
Observe only when settled

Use agent_settled so automatic compaction never aborts a tool-heavy run halfway through.

2
Use Pi’s actual ratio

Read usage.percent; do not estimate tokens or maintain a model table.

3
Trigger at 50%, with hysteresis

Re-arm below 35% after a valid post-compaction response. This prevents repeated compaction loops.

4
Ask Pi to preserve durable meaning

Goals, constraints, decisions + rationale, evidence pointers, dead ends, errors, and next steps—not raw transcripts.

5
Leave the native safety net enabled

The built-in near-overflow trigger still protects unusually long single runs and provider overflow recovery.

Implementation

Built, tested, and distributed

The design sketch below became .shared-llm/public/llm/pi/common/extensions/auto-compact.ts. The shipped version adds TUI/RPC lifecycle guards, stale-callback generations, loud non-UI errors, bounded exponential backoff, and 25 passing behavioral checks. Two consecutive just update runs confirmed idempotent distribution.

Verdict

Thin native trigger extension shipped.

The third-party heuristic engine was not adopted. The new shared runtime uses Pi’s official usage and compaction APIs, keeps the 50% policy explicit, and is already wired into the global Pi extension directory.
